欢迎来到审查者（reviewer）层级！

在本文档中，我们将介绍审查标注任务的基本要点。高质量的训练数据依赖于高质量的审查，因此目标是批准那些准确、一致且符合项目指南的工作。

审查者是人工数据的校对者和编辑，确保输出的内容是体面的，并为团队带来良好的未来数据。审查者往往被要求保持更高的标准，因为你对于策略与原型的知识对于保持团队的高效至关重要。

虽然标注者只对他们自己生成的工作负责，但审查者负责进入他们队列的每一项任务，无论原始所有者是谁。

当只有一层审查时，在你审查完一项任务后，它会立即进入生产。这意味着审查者的错误可能比标注者的错误滚雪球般变成更大的问题。

在一些项目中，有多层审查。在你完成审查后，二级审查可能作为最终审计，或者在标注者和一级审查者就任务应如何标注存在分歧时提供决定性的一票。

### 你需要什么

你作为标注者使用的大多数物品也可以用于你的审查工作。但是，还会有一些额外的材料和访问权限是你完成工作所需要的。

* **电脑：** 请务必与你的团队负责人确认你现有的工作电脑是否适合你的目标项目。

* **审查者项目协议**：当你转到审查者层级时，你的团队负责人或资深审查者可能会为你提供对单独工作流和项目步骤的访问权限。通常，这会附带一堂现场课或一段供你自行复习的录制内容。

* **更新的账户权限**：当你成为审查者时，你的团队负责人需要更新你的账户，因为权限允许你在与标注者相同的项目上看到不同的功能。

## 常见问题：

### 我如何访问 Label Studio？

当你最初获得 Label Studio 访问权限时，你会收到一封电子邮件和一个注册链接。

要访问你公司的项目，请使用你在注册时提供的信息登录。
（位置链接可能会根据你团队是直接在 Label Studio 上工作，还是在你公司自己的集成工作区中工作而有所不同。）

![Screenshot](/images/onboarding/reviewer-0.png)

### 我如何找到我的项目？

你最近的项目会在你登录时显示在主页上。你可以选择将你的优先项目固定到此部分。

![Screenshot](/images/onboarding/reviewer-1.png)

或者，点击仪表板顶部的汉堡菜单（hamburger menu）打开侧边菜单并查看你的“项目（Projects）”文件夹。如果你点击文件夹但没有看到正确的项目列出，你的权限可能尚未更新。请联系你的团队负责人解决此问题。

![Screenshot](/images/onboarding/reviewer-2.gif)

### 你如何进行审查？

1. 选择你想要工作的项目。与标注者流程中的“Label（标注）”按钮不同，你会有一个“Review（审查）”按钮。

   ![Screenshot](/images/onboarding/reviewer-3.png)

2. 点击“Review（审查）”按钮会立即将你带入一个要审查的任务。

   ![Screenshot](/images/onboarding/reviewer-4.png)

3. 或者，如果你直接点击项目名称，你将能够在数据管理器（Data Manager）中以列表格式查看任务队列。此视图还允许你查看谁标注了任务、任何特定排队任务上有多少标注，以及它是否已被批准。

   ![Screenshot](/images/onboarding/reviewer-5.png)

4. 与标注流程类似，请务必遵循你的团队负责人提供的关于如何进行审查的项目协议。

   审查流程可能包括：

   - 直接在任务上修复标注。例如，下图显示审查者正在调整图像上的区域。

        ![Screenshot](/images/onboarding/reviewer-6.gif)

   - 为标注者留下评论，以更好地理解他们可能犯的任何错误或审查者的思考过程。留下评论时，你可以选择将评论链接到标注的特定部分，方法是点击右下角带有聊天气泡的框，该框位于“Add a comment（添加评论）”框旁边。这是向标注者提供针对性反馈的好方法。

        ![Screenshot](/images/onboarding/reviewer-7.png)

5. 与标注流程类似，你可以在页面底部选择“Reject（拒绝）”或“Accept（接受）”。

   ![Screenshot](/images/onboarding/reviewer-8.png)

6. 在任务被审查后，任务的队列状态会更新。如果你（审查者）没有接受标注，它可以被循环回给标注者进行修复。

### 我如何查看我的审查统计？

1. 点击 LSE 平台顶部的汉堡菜单按钮。

2. 点击 Analytics（分析）。

   ![Screenshot](/images/onboarding/reviewer-9.png)

3. 在仪表板左上角选择“Reviews（审查）”。

   你的整体统计会包含在此仪表板中。你可以看到你提交的总审查数、用于审查的时间，以及“接受（accepted）”、“修复+接受（fixed+accepted）”和“拒绝（rejected）”任务之间的比率。

   这些图表还直观地展示了你随时间的生产流程。如果你想调整日期范围，可以在分析仪表板的右上角进行。

   ![Screenshot](/images/onboarding/reviewer-10.png)

4. 如果你愿意，你还可以导出你的分析以供自己记录。

   ![Screenshot](/images/onboarding/reviewer-11.png)

### 当我遇到问题时应该怎么做？

如果你遇到技术问题，请务必记录你看到它们的时间。根据这是一次性问题还是反复出现的问题，收集信息，例如哪些任务（如果特定于任务）受到影响，并将其提交给你的团队负责人。

截取截图，看看你是否能在多个任务上复现相同的问题。此外，如果可能，确定这是仅影响标注者还是审查者的问题，或者是否可能是数据问题。

如果你注意到某个特定标注者反复出现问题，你也应该同样记录任何过去的实例，以便你的负责人掌握所有相关信息来处理该情况。

## 审查者最佳实践

#### 像标注者一样对待每一项任务

虽然审查涉及与标注者不同的流程，但你仍应像从头开始标注它那样评估任务。这意味着评估 LLM 响应中提供的每一个事实性陈述，并验证原始标注者确实检查了任何幻觉。

不要想当然地认为，仅仅因为任务有某种长度或之前的工作者有该主题的 SME（主题专家），就不存在错误或遗漏的问题。事实上，你应该更加留意，因为现在捕捉错误是你的工作。即使是对于最优秀的团队成员，也会由于疏忽或疲劳而发生人为错误。

#### 定期刷新你的审查文档（尤其是如果你已经做了很长时间的审查者）

就像你作为标注者一样，在手边保留一份项目协议的副本会让工作更轻松。通常团队负责人会向审查者提供单独的一套说明和文档，因为工作流可能有所不同，特别是如果项目涉及编辑或退回（sendbacks）。

你可能想要定期检查文档的另一个原因是，当项目转向（pivot）时会有更新伴随而来。你的负责人可能会用任何伴随转向的说明变更来更新它，并且它会作为提醒，不要退回到旧的工作流，即使是偶然的。

#### 不要假设每个人都像你一样处理任务

特别是当原始标注者仍然正确并且任务响应中的所有信息都已验证时，不要因为他们以不同方式进行处理而惩罚他们。如果结论仍然与你的相同，它不会减损工作质量。事实上，模型/LLM 受益于提供多种达到相同答案的方式。

这条规则的主要例外是，如果协议被高层绝对强制要求（通常是因为想要测试特定的逻辑过程），但你的负责人会通知你这些情况。

#### 调查你何时/是否看到趋势并记录它们

区分一次性错误和反复出现的问题很重要。虽然你遇到的错误可能往往属于人为错误（例如，错误标注、遗漏事实性检查等），但故障可能会影响数据标注本身，无论是来自平台的 bug 还是数据集的问题。如果这不是持续的技术问题，请务必记录它以供将来参考，并在再次看到时向你的团队提出。

另一种可能的趋势是标注者对新指南的反复误解。在这种情况下，请咨询其他审查者并汇总适当的信息，以便你们可以共同向负责人提出。

积极的模式也应该被记录，例如项目评分平均值稳步上升，因为这些小事实有助于团队士气。你的负责人可能并不总是能这么快注意到这些，因为他们当时可能专注于其他分析，但观察到的改进也会受到赞赏。

#### 识别文档中可能的空白

虽然入职和协议文档应该提供项目的整个流程和指导，但有可能存在高层未预见的问题。随着大多数数据集复杂查询的增加，往往会引入细微差别，并且不一定能以二元函数进行评估。

例如，如果提示提到“a handful of ideas（一些想法）”，由于使用了没有直接数值含义的词，就引入了一定程度的主观性。不同的数据工作者可能会以各种方式解释“handful”。此时，负责人需要进行整体裁决；没有它，审查者可能会对类似任务评分不一致，从而在标注者中造成困惑。让这种情况持续到你负责人进行审计，会给每个人带来更多工作。

#### 在可能的情况下，主动将自己作为资源

在你安顿好审查职责后，主动为新团队成员回答问题，或主动帮助带头进行技能提升培训或学习会议。协作有助于在团队中共享项目知识，并确保所有成员（标注者和审查者）保持一致。

这会向你的负责人表明你是一个团队合作者，并且可能准备好承担更有趣的工作或职责。协助确保所有标注者和审查者都得到同等的培训，还会产生一个额外的副作用，即让你的工作更轻松。

#### 提供对每项任务都有帮助、适用的反馈

特别是在项目开始或新一波人员入职时，要详细说明哪些方面需要修复，以及为什么。这是一个学习过程，这类评论能促进改进。

#### 注意你的审查可能如何影响个人士气

虽然负责人应该主要关注这一点，但审查者在这方面也有一部分责任。有动力的团队成员是更高效的工人，这也可能减少每个任务的错误数量。

当错误发生时，建设性的批评是必要的，但以善意的（或甚至只是中性的）方式构建它，会减少团队的泄气和摩擦。反馈的目的是改善整个模型，因此，虽然标注者应该学会不要把它个人化，但审查者也应在措辞上小心。

#### 知道何时/是否要求你的负责人将你循环回标注者

请记住，审查和标注是两种不同的工作流，因此必须不要将一种流程视为比另一种“更高”或“更重要”。一些工作者的技能更适合标注，更喜欢它作为他们唯一需要担心的就是自己任务和研究的唯一工作。如果你发现你不像标注那样享受审查，随时让你的负责人知道。

如果你因持续审查而感到倦怠，你可以请求暂时被放回标注池，因为工作流的差异可能有助于“重置”你的工作方式。
