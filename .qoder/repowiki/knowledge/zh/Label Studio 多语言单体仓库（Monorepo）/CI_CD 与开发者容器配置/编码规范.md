- 工作流之间通过 `uses: ./.github/workflows/<name>.yml` 进行组合调用，并在顶层 pipeline 中以 `needs` 声明依赖顺序，避免在每个 workflow 中重复实现公共步骤。
- 可复用的 CI 步骤（如前端环境初始化）抽取为 `.github/actions/<name>/action.yml` 复合 action，通过 `inputs` 暴露 node-version、directory 等参数。
- 对 PR 分支变更采用 `dorny/paths-filter` 将变更分类为 src/frontend/docker/migrations，下游 job 统一通过 `needs.changed_files.outputs.<category> == 'true'` 条件启用。
- 需要 GitHub API 写权限的步骤显式声明 `permissions: contents: write` / `pull-requests: write`，而非默认 token。
- 所有 workflow 顶部设置 `concurrency.group` 并开启 `cancel-in-progress: true`，保证同一 PR 的新提交会取消旧 run。
- 对外部仓库（如 HumanSignal/actions-hub）通过 `actions/checkout` 单独 checkout 到 `.github/actions-hub` 后再 `uses: ./.github/actions-hub/actions/...` 引用，保持私有 action 与源码解耦。
