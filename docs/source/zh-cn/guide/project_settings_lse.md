## 常规（General）

使用这些设置来指定有关项目的一些基本信息。

| 字段          | 描述    |
| ------------- | ------------ |
| **工作区（Workspace）**         | 为项目选择 [工作区](workspaces)。 |
| **项目名称（Project Name）** | 输入项目的名称。 |
| **描述（Description）**       | 输入项目的描述。 |
| **颜色（Color）**      | 你可以为项目选择一种颜色。在查看“项目”页面时，项目会以这种颜色高亮显示。 |
| **代理凭据（Proxy Credentials）**     | 输入代理凭据。如果你的任务数据受到基本 HTTP 访问认证的保护，这些可能是必需的。<br><br> 例如，如果你的 Label Studio 实例需要通过企业代理服务器访问互联网。 |

## 标注界面（Labeling interface）

标注界面是项目的中心配置点。这决定了任务如何呈现给标注者。

有关设置标注界面的信息，请参阅 [标注配置](setup)。

## 成员（Members）

使用此部分来添加和删除项目成员。你只能为公共项目（意味着项目不在你的个人沙箱工作区中）配置项目成员。

##### 添加成员

点击 **添加成员（Add Members）** 打开一个窗口，你可以在其中搜索并将成员添加到项目。根据你的组织的权限设置，你可能还能够邀请新用户加入组织并自动将其添加到项目。

!!! info 提示
    如果你是管理员或所有者角色，你可以从 **组织 > 成员（Organization > Members）** 页面批量分配用户到工作区和项目。

##### 用户角色与成员资格

| 角色 | 成员资格 |
| ------------- | ------------ |
| **管理员和所有者（Admins and Owners）** | 不能从公共项目中添加或删除。这些用户有权访问所有项目，无论状态如何，除非项目位于个人沙箱工作区中。 |
| **经理（Managers）** | 必须被添加到项目或父工作区才能获得访问权限，但一旦添加，无论状态如何，都将有权访问该项目。 |
| **标注者和审查者（Annotators and Reviewers）** | 必须被添加到项目或父工作区才能获得访问权限，但在项目发布之前无法访问项目。 |

##### 继承的成员

在 [工作区级别](workspaces#Add-or-remove-workspace-members) 作为成员添加的经理、审查者和标注者会自动获得工作区内任何项目的成员资格。

管理员和所有者拥有继承的成员资格，因为他们有权访问组织内的所有公共项目。

##### 标注者角色

标注者角色是 Label Studio 中限制最多的角色，默认情况下，标注者只能访问标注流，在那里他们看到准备好标注的任务。

* 如果你启用了 [自动分配（Automatic distribution）](#distribute-tasks)，具有标注者角色的用户在作为成员添加时会自动分配任务。类似地，默认情况下，具有审查者角色的项目成员能够在任务被标注后开始审查标注。
* 如果你启用了 [手动分配（Manual distribution）](#distribute-tasks)，在将具有标注者角色的用户作为项目成员添加之前，你需要先添加他们。如果你启用了 [**仅审查手动分配的任务（Review only manually assigned tasks）**](#reviewing-options)，具有审查者角色的用户也必须是项目成员才能被分配到任务。

##### 项目级角色

对于在组织级别应用了标注者或审查者角色的用户，你可以根据需要在项目之间更改他们的角色。

例如，如果 Heidi Opossum 在组织级别被授予标注者角色，但你希望她在“项目 1”中作为审查者工作，你可以将她的项目级角色设置为审查者。

要分配项目级角色，请首先将此人添加到你的项目。添加后，你可以使用下拉菜单更改他们的角色：

![Screenshot](/images/project/member_roles.png)

!!! note
    这仅适用于在组织级别应用了标注者或审查者角色的用户。具有经理、管理员和所有者角色的用户不能将其权限在每个项目基础上降级为标注者或审查者。

## 标注（Annotation）

使用这些设置来配置标注者将看到的选项以及他们的标注任务如何分配。

<dl>

<dt>标注说明（Annotation Instructions）</dt>

<dd>

指定要展示给标注者的说明。

此字段接受 HTML 格式，包括 iframe（点击 **预览（Preview）** 检查你的格式）。

!!! note
    如果你使用 HTML 格式并想要包含 CSS 样式，请使用 `<Style>` 块，因为内联样式在保存时会被删除。

启用 **在标注前显示（Show before labeling）** 以在标注者进入标注流时向他们显示弹出消息。如果禁用，用户将需要点击标注界面底部的 **显示说明（Show instructions）** 操作。

从数据管理器（Data Manager）单独打开任务（快速视图，Quick View）时，说明不会弹出。

</dd>

<dt id="distribute-tasks">任务分配（Task Assignment）</dt>

<dd>

选择你希望如何将任务分配给标注者进行标注。

| 字段          | 描述    |
| ------------- | ------------ |
| **自动（Automatic）**         | 标注者被自动分配给任务，并且手动分配标注者的选项被禁用。自动分配会分配给所有具有标注者角色且是项目 [成员](#Members) 的用户。<br /><br />你可以在 [**质量（Quality）** 设置](#Quality) 中进一步定义自动分配工作流。<br /><br />当使用自动分配时，你还将在整个项目设置中拥有额外的配置选项，例如任务排序、任务保留以及 **质量** 下的许多设置。 |
| **手动（Manual）** | [手动分配](manage_data#Assign-annotators-to-tasks) 任务给标注者并直接管理他们的工作量。标注者将在你分配给他们后能够开始任务。 |

</dd>

<dt id="task-ordering">任务排序方法（Task Ordering Method）</dt>

<dd>

*仅在 使用自动任务分配时可用。*

选择将任务呈现给标注者的顺序。

| 字段          | 描述    |
| ------------- | ------------ |
| **按任务 ID（By Task ID）** | 任务按 ID 升序显示给标注者。 |
| **随机（Random）** | 任务以随机顺序显示。 |
| **不确定性（Uncertainty）**         | 此选项适用于当你使用机器学习后端并想要采用 [主动学习](active_learning) 时。主动学习模式持续训练并审查来自连接的机器学习模型的预测，使模型能够随着新标注的创建而迭代改进。<br /><br />启用不确定性采样（Uncertainty Sampling）时，Label Studio 战略性地从你的模型中选择预测分数最不自信或最不确定的任务。目标是在最小化需要标注的数据量的同时最大化模型的性能。 |

</dd>

<dt id="lock-tasks">任务保留（Task Reservation）</dt>

<dd>

*仅在 使用自动任务分配时可用。*

控制任务为标注者保留多长时间。

任务保留确保标注者开始处理的任务被他们暂时保留，防止其他标注者在保留到期之前访问相同的任务。这有助于管理任务分配并保持项目进度的高效。

!!! note

    任务保留会考虑重叠（[**质量 > 每个任务的标注数（Annotations per task）**](#overlap)）。例如，如果你的重叠是 `2`，则两个标注者可以同时保留一个任务。

    当 [**任务分配（Task Assignment）**](#distribute-tasks) 设置为 **手动（Manual）** 时，任务保留设置是隐藏的，因为它不适用。

一旦标注者打开任务，就会实施任务保留。保留一直持续到以下情况之一发生（以最先发生的为准）：

* 任务保留时间到期。
* 标注者提交了任务。
* 标注者跳过了任务，并且项目的 **跳过队列（Skip Queue）** 设置是 **将跳过的任务重新排队给其他人的（Requeue skipped tasks to others）** 或 **忽略跳过的（Ignore skipped）**。

**建议的保留时间**

默认情况下，任务保留时间为 1440 分钟（1 天）。这是任务保留所允许的最长时间。

设置保留时间时，你的目标应该是允许比完成任务所需的最长时间略多一点。

* **关于允许时间过长的说明**

    如果你为任务保留留出过多时间，你可能会面临一些用户被阻塞的风险。

    例如，假设你有多个标注者在一个项目上工作。你的最小标注重叠设置为 `2`。

    如果你的某些标注者浏览他们的标注队列寻找最容易完成的任务，他们可能会无意中留下大量被锁定的任务。根据项目的大小和你工作的标注者数量，这可能导致一些标注者无法继续他们的工作，直到任务保留时间到期。

* **关于允许时间过短的说明**

    如果你将保留时间设置得太低，你可能会发现你有许 多超过最小重叠设置的任务。

    例如，假设你有多个标注者在一个项目上工作。你的最小标注重叠设置为 `2`。

    两个标注者开始处理一项任务，他们两人都花了 15 分钟完成，但你的保留时间是 10 分钟。这意味着 10 分钟后，另一个标注者也可以开始处理该任务 —— 导致该任务上有 3 个标注而不是 2 个（你的最小标注者重叠）。

    你可以通过在 [**质量 > 标注重叠（Quality > Overlap of Annotations）**](#overlap) 下选择 **强制严格重叠（Enforce strict overlap）** 来帮助避免这种情况。

</dd>

<dt id="annotating-options">标注选项（Annotation Options）</dt>

<dd>

为标注者配置附加设置。

| 字段          | 描述    |
| ------------- | ------------ |
| **允许空标注（Allow empty annotations）** | 这决定了标注者是否可以在不对任务进行任何标注的情况下提交任务。如果启用，标注者即使没有添加任何标签或区域也可以提交任务，从而产生空标注。 |
| **向标注者显示数据管理器（Show Data Manager to annotators）** | 禁用时，标注者只能进入标注流。启用时，标注者可以访问数据管理器。对他们可用的任务取决于任务是如何分配的：<ul><li>自动任务分配：标注者只能看到他们已完成或已创建草稿的任务。</li><li>手动任务分配：标注者只能看到分配给他们的任务。</li></ul>请注意，某些信息对标注者仍然是隐藏的，他们只能查看数据管理器列的子集。例如，他们看不到“标注者（Annotators）”、“一致性（Agreement）”、“审查者（Reviewers）”等列。 |
| **仅向标注者显示标注配置中使用的列（Show only columns used in labeling configuration to Annotators）** | （仅当上一个设置启用时可用）<br><br /> 向标注者隐藏未使用的数据管理器列。<br><br />未使用的数据管理器列是包含未用于标注配置的数据的列。<br><br />例如，你可能包含想要作为项目一部分查看的元数据或系统数据，但你不一定想将这些数据暴露给标注者。 |

</dd>

<dt id="skip">任务跳过（Task Skipping）</dt>

<dd>

配置与标注流中 **跳过（Skip）** 操作相关的设置。

| 字段          | 描述    |
| ------------- | ------------ |
| **允许跳过任务（Allow skipping tasks）**         | 使用此选项来显示或隐藏标注者的 **跳过（Skip）** 操作。 |
| **跳过时需要评论（Require comment to skip）** | 启用时，标注者在跳过任务时需要留下评论。 |

!!! info 提示
    你可以在任务的 JSON 源中将单个任务配置为不可跳过。更多信息，请参阅 [单个不可跳过任务](skip#Individual-unskippable-tasks)

</dd>

<dt id="skip-queue">跳过队列（Skip Queue）</dt>

<dd>

选择你希望如何处理跳过的任务。要禁止跳过任务，你可以在上面的 **任务跳过（Task Skipping）** 部分隐藏 **跳过** 操作。

<table>
<thead>
    <tr>
      <th>字段</th>
      <th>描述</th>
    </tr>
</thead>
<tr>
<td>

**将跳过的任务重新排队回给标注者（Requeue skipped tasks back to the annotator）**

</td>
<td>

如果标注者跳过一项任务，该任务会被移动到他们队列的底部。当他们到达队列末尾时，会再次看到该任务。

如果标注者在标注跳过的任务之前退出了标注流，然后稍后重新进入标注流，他们是否再次看到该任务取决于任务分配的设置方式。

* 自动任务分配：他们是否再次看到任务取决于此后是否有其他标注者完成了该任务。如果标注者重新进入标注流时任务仍未完成，他们可以更新标签并重新提交任务。
* 手动任务分配：标注者将继续看到跳过的任务，直到其完成。

跳过的任务不会被标记为已完成，并且会影响可从项目仪表板查看的“项目总体进度（Overall Project Progress）”计算。（这意味着有跳过任务的项目进度将低于 100%。）

</td>
</tr>
<tr>
<td>

**将跳过的任务重新排队给其他人（Requeue skipped tasks to others）**

</td>
<td>

*仅当 使用自动任务分配时适用。*

如果标注者跳过一项任务，该任务会从他们的队列中移除并自动分配给不同的标注者。

在跳过任务并完成他们的标注队列后，该标注者无法返回到跳过的任务。

如果没有其他标注者分配给该任务，或者所有标注者都跳过了该任务，则该任务保持未完成。

跳过的任务不会被标记为已完成，并且会影响可从项目仪表板查看的“项目总体进度”计算。（这意味着有跳过任务的项目进度将低于 100%。）

请注意，如果你在切换到手动模式之前选择了此选项，此选项保持选中状态，并且行为与 **忽略跳过的** 相同。

</td>
</tr>
<tr>
<td>

**忽略跳过的（Ignore skipped）**

</td>
<td>

此设置的工作方式取决于你的任务分配方法。

* 自动任务分配：如果标注者跳过一项任务，该任务会从标注者的队列中移除。

    如果任务重叠（如 [**质量 > 每个任务的标注数（Annotations per task）**](#overlap) 中所定义）设置为 1，则跳过的任务被标记为已完成，标注者不再看到它。但是，如果重叠大于 1，则该任务会显示给其他标注者，直到达到最小标注数。

* 手动任务分配：如果标注者跳过任务，它会从他们的队列中移除。但分配给该任务的其他标注者仍会在他们的队列中看到它。

对于两种分配方法，**忽略跳过的** 在计算进度时对跳过任务的处理方式不同。

与其他跳过队列选项不同，在这种情况下，跳过的任务不会对可从项目仪表板查看的“项目总体进度”计算产生不利影响。（这意味着有跳过任务的项目进度仍然可以达到 100%，假设所有其他任务都已完成。）

</td>
</tr>

<dd>

| ------------- | ------------ |

| **交互式显示预标注（Reveal pre-annotations interactively）** | 启用时，预标注区域（如边界框或文本片段）不会自动显示给标注者。相反，标注者可以绘制一个选择矩形以显示该区域内的预标注区域。这允许标注者先审查图像或文本，而不受模型预测的影响。预标注区域必须具有 `"hidden": true` 属性。<br /><br />当你有多个低置信度区域、不想一次全部显示以避免混乱时，此功能特别有用。 |

</dd>

## 审查（Review）

使用这些设置来配置审查者将看到的选项。

<dl>

<dt>说明（Instructions）</dt>

<dd>

指定要展示给审查者的说明。此字段接受 HTML 格式。

启用 **在审查前显示（Show before reviewing）** 以在审查者进入标注流时向他们显示弹出消息。如果禁用，用户将需要点击标注界面底部的 **显示说明（Show instructions）** 操作。

</dd>

<dt id="reviewing-options">审查选项（Reviewing Options）</dt>

<dd>

使用此部分来配置：

* 需要多少个已接受/已拒绝的标注，任务才被视为已审查（从 **需要审查（Needs Review）** 状态移动到 **已完成（Done）** 状态）。

* 需要多少个已提交的标注，任务才能进入 **需要审查** 状态。

* 审查者是否只能看到分配给他们自己的任务。

更多信息关于状态，请参阅 [项目状态](project_states)。

!!! note
    从 **需要审查** 移动到 **已完成** 会影响以下内容：

    * **审查流（Review stream）**：处于 **已完成** 状态的任务不会显示在审查流中（审查者点击 **审查所有任务（Review All Tasks）** 时看到的内容）。
    * **数据管理器**：**已审查（Reviewed）** 列中显示的值。
    * **导出**：当你只想在导出快照中包含已审查的任务时，包含哪些任务。
    * **仪表板**：与审查相关的各种计数和指标。

<table>
<thead>
    <tr>
      <th>字段</th>
      <th>描述</th>
    </tr>
</thead>
<tr>
<td>

**在至少一个已接受标注后任务被视为已审查（Task is reviewed after at least one accepted annotation）**

</td>
<td>

对于已提交标注的合格任务（进入 **需要审查** 状态的任务），审查者只需要接受一个标注即可认为任务完成。

</td>
</tr>
<tr>
<td>

**在所有标注都被审查后任务被视为已审查（Task is reviewed after all annotations are reviewed）**

</td>
<td>

对于已提交标注的合格任务（进入 **需要审查** 状态的任务），审查者需要接受或拒绝 **所有** 标注，才能认为任务完成。

</td>
</tr>
<tr>
<td>

**仅审查手动分配的任务（Review only manually assigned tasks）**

</td>
<td>

如果启用，审查者只能看到分配给他们自己的任务。

这也意味着，如果启用此选项且没有分配审查者，任务可以直接从 **标注中（Annotating）** 状态进入 **已完成** 状态。

</td>
</tr>
<tr>
<td>

**在审查流中仅显示已完成的任务（Show only finished tasks in the review stream）**

</td>
<td>

启用时，只有当任务达到其标注要求时，才被视为准备好审查。

如果你的项目使用 [自动分配](#distribute-tasks)，则这意味着任务已达到 [**每个任务的标注数** 阈值](#overlap)。

如果你的项目使用 [手动分配](#distribute-tasks)，则这意味着所有分配的标注者都已提交标注。

请注意，在大多数情况下，跳过的任务不计入满足最小值。

</td>
</tr>
</table>

</dd>

<dt id="review-sampling">审查抽样（Review Sampling） <span class="badge"></span></dt>

<dd>

确定需要多少个合格任务需要被审查。

“合格（Eligible）”任务首先由你是否启用了 **在审查流中仅显示已完成的任务（Show only finished tasks in the review stream）** 来定义：

* 如果启用，则合格任务仅包括那些已由所有必需标注者完成的任务。
* 如果未启用，只要任务至少有一个已提交的标注，它就有资格接受审查。

合格任务进入 **需要审查** 状态，这意味着它们被包含在审查流中。

!!! note

    例如，将 **基本抽样（Basic Sampling）** 设置为 50% 并不能保证恰好一半的合格任务会被审查 —— 实际份额将围绕 50% 波动，项目任务越多，方差越小。

<td>

一次审查一个标注者的标注。该流在该标注者剩余工作的设定百分比被覆盖后，再优先处理另一个标注者。

<p>选择此选项时，请设置 <b>每个标注者的审查覆盖率（Review Coverage per Annotator (%)</b>）：</p>

<ul>

<li>一轮期间提交的标注算作剩余工作，因此该轮会随着它们而增长。</li>

使用这些设置来确定任务完整性和一致性指标。

<dt id="overlap">标注重叠（Overlap of Annotations）</dt>

<dd>

!!! note
    重叠设置仅在项目使用自动分配模式时适用。如果你使用手动分配模式，所有任务都必须手动分配 —— 这意味着你也在手动确定重叠。

默认情况下，每个任务只需要由一个标注者标注。如果你想要多个标注者标注相同的任务，请增加 **每个任务的标注数（Annotations per task）**。

<table>
<thead>
    <tr>
      <th>字段</th>
      <th>描述</th>
    </tr>
</thead>
<tr>
<td>

**每个任务的标注数（Annotations per task）**

</td>
<td>

你想要允许每个任务的不同标注数量。

请注意，在某些情况下，这可能被超过。例如，如果项目中存在长期存在的草稿，或者你的 [任务保留](#lock-tasks) 时间非常低。

另请注意，只有由不同用户创建的标注才计入重叠。例如，如果重叠是 `2`，并且用户在一单个任务上创建并提交了两个标注（这可以在快速视图中完成），在另一个用户提交标注之前，重叠阈值将无法达到。

</tr>
<tr>

</td>

- 对 100% 的任务强制执行重叠。

- 将标注数设置为 **3**
- 对 50% 的任务强制执行重叠。

<tr>

</td>
<td>

请注意，如果启用，此设置会取代你在 [**标注 > 任务排序方法（Annotation > Task Ordering Method）**](#task-ordering) 中指定的内容。

</td>

</td>

启用时，如果标注者在达到限制后尝试提交任务，他们将收到一条错误消息，指出 **已达到标注重叠（Annotation Overlap Reached）**。他们的草稿将被保存，但他们将无法提交。<br /><br />

</tr>

<dt id="annotation-limit">每个标注者的任务限制（Tasks Per Annotator Limit） <span class="badge"></span></dt>

<dd>

为每个用户可标注的任务数量设置限制。如果你担心少数超级用户完成大部分项目任务可能产生的任何潜在偏差，这会很有用。

当标注者达到其限制时，他们将看到一条通知，告诉他们已被暂停。这是一个灵活的暂停：标注者无法开始任何新的标注工作，但他们保留对项目的访问权限，以便他们可以更新审查者已拒绝的标注。更多信息，请参阅 [完全与灵活暂停](quality#Full-and-flexible-pauses)。

启用 **限制每个标注者的任务数（Limit tasks per annotator）** 时，你将看到以下选项：

| 字段          | 描述    |
| ------------- | ------------ |
| **按任务数量限制（Limit by Number of Tasks）**    | 设置每个标注者在进度暂停之前能够完成的特定任务数量。   |
| **按任务百分比限制（Limit by Percentage of Tasks）** | 将每个标注者能够完成的任务数量计算为项目内任务的百分比。  |

你可以设置一个或两个值。标注者达到较小的限制时将被暂停。

要取消暂停标注者：

* 如果你提高限制，先前被暂停的标注者将重新获得访问权限。
* 如果你使用基于百分比的限制，并且你向项目添加了更多任务，先前被暂停的标注者将重新获得访问权限。

有关暂停标注者的更多信息，包括如何手动暂停特定标注者，请参阅 [暂停标注者](quality#Pause-an-annotator)。

!!! note
    暂停对标注者和审查者角色的用户强制执行。

    由于这是一个灵活的暂停，它只停止新的标注工作。因此，例如，如果审查者也在标注任务，并且他们达到了标注限制，他们可以继续审查其他人的标注。

    经理、管理员或所有者角色的用户不受任务限制的影响。

</dd>

<dt id="annotator-eval">标注者评估（Annotator Evaluation）<span class="badge"></span></dt>

<dd>

!!! note
    标注者评估设置仅在项目配置为 [自动分配任务](#distribute-tasks) 时可用。如果你使用手动分配，此部分不会出现在你的项目设置中。

    如果你将项目从自动切换到手动分配，标注者评估会自动禁用。

根据 [真实标签](ground_truths) 或根据他们的审查结果 **接受分数（acceptance score）** 来评估标注者。然后你可以自动暂停未达到你设定的阈值的标注者。

!!! note
    当你根据真实标签评估时，这些任务不受 [标注者重叠](#overlap) 的约束。例如，如果你将重叠设置为 `2`，但你有 10 个标注者，所有 10 个仍然能够向真实标签任务添加标注。

!!! info 提示
    你可以通过将 `"allow_skip": false` 作为你导入到项目中的 JSON 任务定义的一部分，来指定真实标签任务应该是不可跳过的。更多信息，请参阅 [单个不可跳过任务](skip#Individual-unskippable-tasks)

</td>

</table>

你可以从 **成员（Members）** 页面查看每个标注者的评估状态以及谁被暂停。

当用户作为标注者评估工作流的一部分被暂停时，你不能从成员暂停开关手动取消暂停他们。如果他们的分数恢复，他们会自动取消暂停。你也可以放宽项目的评估设置，例如通过增加最小样本或更改分数阈值。

如果你的项目将已拒绝的标注重新排队，被暂停的标注者仍然可以从标注流和数据管理器接收并更新他们被拒绝的工作。当你根据接受分数评估时，更新被拒绝的标注本身不会解除暂停；审查者必须记录一个提高分数的新裁决。更多信息，请参阅 [从灵活暂停中恢复](quality#Recover-from-a-flexible-pause)。

有关暂停标注者的更多信息，包括如何手动暂停特定标注者，请参阅 [暂停标注者](quality#Pause-an-annotator)。

!!! note
    暂停对标注者和审查者角色的用户强制执行。

    由于这是一个灵活的暂停，它只停止新的标注工作。因此，例如，如果审查者也在标注任务，并且他们评估失败，他们可以继续审查其他人的标注。

    经理、管理员或所有者角色的用户不受评估要求的影响。

</dd>

<dt id="task-agreement">一致性（Agreement） <span class="badge"></span></dt>

<dd>

当多个标注者标注一项任务时，任务一致性反映了标注者之间的一致性程度。

例如，如果 10 个标注者审查一项任务，只有 2 个选择了相同的选项，那么该任务的一致性分数会很低。

你可以自定义任务一致性如何计算以及它应如何影响项目工作流。更多信息，请参阅 [任务一致性](stats)。

!!! error Enterprise

## 模型（Model）

点击 **连接模型（Connect Model）** 以将机器学习（ML）后端连接到你的项目。有关连接模型的信息，请参阅 [机器学习集成](ml)。

你具有以下配置选项：

| 字段          | 描述    |
| ------------- | ------------ |
| **在提交标注时开始模型训练（Start model training on annotation submission）**         | 每次创建或更新标注时触发连接的 ML 后端启动训练过程。<br /><br />这是 [主动学习循环](active_learning) 的一部分，随着新标注添加到数据集，模型可以持续改进。启用此设置后，将调用 ML 后端的 `fit()` 方法，使模型能够从最新标注中学习，并可能改善其对后续任务的预测。   |
| [**交互式预标注**](ml#interactive-pre-annotations)         | （在创建或编辑模型连接时可用）<br /><br />启用此选项以允许模型通过在进行任务时提供实时预测或建议来辅助标注过程。<br /><br />换句话说，当你与数据交互时（例如，在图像上绘制区域、高亮文本或向 LLM 提问），ML 后端会接收此输入并返回基于它的预测。   |

并且以下操作可从连接的模型旁边的溢出菜单中获得：

| 操作          | 描述    |
| ------------- | ------------ |
| **开始训练（Start Training）**         | 手动启动训练。如果你想控制模型训练发生的时间（例如，在收集了特定数量的标注后或在某些时间间隔），请使用此操作。  |
| **发送测试请求（Send Test Request）**         | （可从连接的模型旁边的溢出菜单中获得）<br /><br />将此用于故障排查并向连接的模型发送测试请求。   |
| **编辑（Edit）**         | 编辑模型名称、URL 和参数。更多信息，请参阅 [将模型连接到 Label Studio](ml#Connect-a-model-to-Label-Studio)。 |
| **删除（Delete）**         | 移除与模型的连接。 |

## 预测（Predictions）

从这里你可以查看已导入的预测、使用 [Prompts](prompts_predictions) 生成的预测，或执行来自数据管理器的 **批量预测（Batch Predictions）** 操作时生成的预测。有关使用预测的更多信息，请参阅 [将预标注数据导入 Label Studio](predictions)。

要从项目中删除预测，请点击预测集旁边的溢出菜单并选择 **删除（Delete）**。

要确定向标注者显示哪些预测，请使用 [**标注 > 实时预测（Annotation > Live Predictions）** 部分](#Annotation)。

## 云存储（Cloud storage）

在这里你可以将 Label Studio 连接到云存储提供商：

* **源云存储（Source Cloud Storage）** —— 这是你项目的源数据保存的地方。当你同步源存储时，Label Studio 检索要标注的数据。
* **目标云存储（Target Cloud Storage）** —— 这是你的标注保存的地方。当你同步目标存储时，标注会从 Label Studio 发送到目标存储位置。

更多信息，请参阅 [从外部存储同步数据](storage)。

## 危险区域（Danger Zone）

从这里，你可以访问会导致数据丢失的操作，应谨慎使用。

* **重置缓存（Reset Cache）**

    重置标注缓存。在你看到有关某些标签的验证错误 —— 但你知道这些标签不存在的情况下，这会有所帮助。

* **删除所有标签页（Drop All Tabs）**

    如果数据管理器未加载，删除所有数据管理器标签页会有所帮助。

* **删除项目（Delete Project）**

    删除项目会从 Label Studio 中永久移除所有任务、标注和项目数据。
