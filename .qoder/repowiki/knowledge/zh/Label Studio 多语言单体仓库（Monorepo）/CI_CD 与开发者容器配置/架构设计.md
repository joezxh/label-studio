模块按职责划分为四个子目录：
- `.github/workflows/`：以 `cicd_pipeline.yml` 为入口，通过 `dorny/paths-filter` 按 src/frontend/docker/migrations 四类变更触发 bandit/ruff/biome/pytest/migrations/docker-build/yarn 等并行 job，并由 `check_gate` 聚合；`release-pipeline.yml` 负责正式发布（Docker 镜像推广、PyPI 上传、Helm Chart 更新、Homebrew Tap 通知）。
- `.github/actions/`：仅包含一个 composite action `setup-frontend-environment`，封装 Node/Bun 安装与依赖缓存逻辑，被前端测试工作流复用。
- `.github/helpers/gh_changelog_generator/`：发布 changelog 生成脚本，由 release workflow 调用。
- `.devcontainer/`：基于 `docker-compose.yml` 启动 `app` + `db` 服务，`devcontainer.json` 声明 VS Code 扩展与 Python 解释器路径，提供本地一致的开发体验。

外部依赖方向：workflow 通过 `uses: ./.github/workflows/<x>.yml` 组合调用其他工作流，并通过 `actions/checkout` 拉取 `HumanSignal/actions-hub` 仓库中的私有 actions（如 jira-set-fix-version、github-changelog），形成“本仓库编排 + actions-hub 执行”的两层结构。
