- 每个业务功能以独立 Django app 形式存在，包含 `models.py`、`serializers.py`、`api.py`（DRF ViewSet）、`urls.py`、`migrations/`、`tests/` 的标准结构。
- 可插拔行为通过 `core/settings/base.py` 中的字符串设置钩子暴露（如 `TASK_SERIALIZER`、`DATA_MANAGER_ACTIONS`、`GET_STORAGE_LIST`、`USER_SERIALIZER`），由运行时动态 import 解析。
- 外部依赖（数据库、存储、邮件、日志等）全部通过环境变量读取，使用 `core.utils.params.get_env/get_bool_env/get_env_list` 封装，避免硬编码。
- io_storages 下的每种存储后端（s3/gcs/azure_blob/localfiles/redis）遵循相同的子包结构：`__init__.py`、`models.py`、`serializers.py`、`api.py`、`form_layout.yml`、可选 `utils.py`/`functions.py`。
- FSM 相关模块（annotation/task/project transitions）集中放在 `fsm/` 包内，并通过 `registry.py` 注册，业务 app 仅引用而非直接耦合。
- 测试采用 pytest + tavern YAML 进行端到端 API 测试，同时在各 app 的 `tests/` 目录下保留单元测试与工厂类。
