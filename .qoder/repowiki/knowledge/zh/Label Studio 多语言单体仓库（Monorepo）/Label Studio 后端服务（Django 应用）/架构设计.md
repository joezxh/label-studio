以 Django 为框架，`server.py` 作为 CLI 入口（`label-studio start/init/reset_password/user/version/export/calculate_stats_all_orgs/shell`），通过 `core.settings.label_studio` 加载配置并调用 `django.core.management.call_command('runserver')` 启动 WSGI。

- 顶层包按业务域拆分为多个独立 Django app：`core`（设置、中间件、模板、静态资源、工具）、`users`、`organizations`、`projects`、`tasks`、`data_manager`、`data_import`、`data_export`、`io_storages`（S3/GCS/Azure Blob/Localfiles/Redis 插件式实现）、`ml`、`ml_models`、`ml_model_providers`、`webhooks`、`labels_manager`、`fsm`（状态机）、`jwt_auth`、`session_policy`，均在 `base.py` 的 `INSTALLED_APPS` 中注册。
- URL 路由集中在 `core/urls.py`，使用 `include()` 将各 app 的 `urls.py` 挂载到根路径；DRF 通过 `drf_spectacular` 生成 OpenAPI（`/docs/api/schema/*`）。
- 扩展点机制：`core/settings/base.py` 定义大量可覆盖的设置钩子（如 `TASK_SERIALIZER`、`DATA_MANAGER_ACTIONS`、`GET_STORAGE_LIST`、`USER_SERIALIZER`、`PROJECT_MIXIN` 等），供企业版或下游项目替换行为。
- FSM 模块在 `INSTALLED_APPS` 中排在业务 app 之前，以便 `projects`/`tasks` 在其上注册状态转换；`io_storages` 下每个云厂商子目录遵循统一的 `models.py / serializers.py / api.py / form_layout.yml` 结构。
- 异步任务通过 `django-rq`（RQ_QUEUES: critical/high/default/low），Redis 默认关闭（`REDIS_ENABLED = False`）。
- 前端静态资源由后端直接托管：`EDITOR_ROOT`/`DM_ROOT`/`REACT_APP_ROOT` 指向 `../../web/dist/libs/editor`、`datamanager`、`apps/labelstudio`。
