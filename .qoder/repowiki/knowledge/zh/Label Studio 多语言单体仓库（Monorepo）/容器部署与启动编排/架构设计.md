模块以 `docker-entrypoint.sh` 为唯一入口，根据第一个参数分派四种运行模式：`nginx`（独立 Nginx 容器）、`label-studio-uwsgi`（Django + uWSGI）、`label-studio-migrate`（仅数据库迁移）以及默认的直接 `exec "$@"` 模式；每种模式先按数字前缀顺序执行 `docker-entrypoint.d/<mode>/` 下的可执行 shell 脚本完成运行时装配，再 `exec` 目标进程。

- 初始化脚本分层：`common/` 存放通用逻辑（权限检查、Nginx 配置、CA bundle、DB 等待、迁移），各 mode 子目录通过符号链接或同名文件复用，例如 `app/20-wait-for-db.sh` 指向 `../common/20-wait-for-db.sh`，实现共享逻辑与场景特化的解耦。
- Nginx 作为反向代理，`default.conf` 监听 8085，静态资源与前端由 alias 直接提供，其余请求转发至 `http://localhost:8000`；SSL 证书路径通过 `NGINX_SSL_CERT` 环境变量在启动时 `sed` 替换模板中的占位符。
- uWSGI 由 `uwsgi.ini` 管理，暴露 `core.wsgi:application`，进程数、内存回收、harakiri 超时等关键参数均通过 `UWSGI_*` 环境变量覆盖。
- 构建期脚本：`prebuild.sh` 调用前端 npm 构建并 collectstatic，`install_npm.sh`、`heroku_run.sh` 分别用于 Heroku 平台解析 DATABASE_URL 后走 entrypoint。
- 依赖方向单向：entrypoint → init scripts → 外部服务（Postgres、Nginx、uWSGI/Django），不反向引用 Python 业务代码。
